# Session Persistence Design
**Date:** 2026-05-28
**Status:** Approved

## Problem
`pipeline_result` (top targets, map data, report) and `chat_history` live only in `st.session_state` — both are lost on page refresh or browser close. Users must re-run the expensive 1–2 min pipeline to recover previous results.

## Goal
- Auto-save every pipeline run (including map GeoJSON, top targets, full report) to disk
- Auto-save chat history updates after each message
- Allow loading any past session from the sidebar to restore the full app state (map, scores, report, chat)

## Approach: JSON session files

Chosen over SQLite (overkill for tens of sessions) and sidecar-in-reports (conflates download folder with app state).

---

## Section 1: Storage & File Format

### Directory
`sessions/` at repo root, added to `config.py` as `SESSIONS_DIR` alongside `REPORTS_DIR`.

### Filename
`{location_slug}_{run_id}.json`
- `location_slug`: lowercase, spaces replaced with underscores (e.g. `laguna`, `metro_manila`)
- `run_id`: 8-char UUID fragment already generated by `graph/pipeline.py`
- Example: `sessions/laguna_abc12345.json`

### File schema
```json
{
  "pipeline_result": { ...full SolarLeadState dict... },
  "chat_history":    [ {"role": "user|assistant", "content": "..."} ],
  "saved_at":        "2026-05-28T10:30:00"
}
```

`pipeline_result` is fully JSON-serializable — all fields in `SolarLeadState` are strings, dicts, or lists. Chat history is overwritten (not appended) on each save so the file always reflects current state.

## Section 2: Session Manager Module

New file: `agents/session_store.py`

### Functions

**`save_session(pipeline_result: dict, chat_history: list) -> None`**
- Derives slug from `pipeline_result["location"]`
- Derives run_id from `pipeline_result["run_id"]`
- Writes `sessions/{slug}_{run_id}.json`
- Called: (a) immediately after `run_pipeline()` returns in `app.py`; (b) after each chat message with updated history

**`load_session(filepath: str | Path) -> tuple[dict, list]`**
- Reads JSON file, returns `(pipeline_result, chat_history)`

**`list_sessions() -> list[dict]`**
- Scans `sessions/*.json`
- Returns list of `{path, label, location, run_id, saved_at}` sorted newest-first
- `label` format: `"Laguna — May 28 2026"` (for sidebar dropdown)

No new dependencies — stdlib `json`, `pathlib`, `datetime` only.

## Section 3: UI Changes in `app.py`

### Auto-save (sidebar, after pipeline run)
```python
result = run_pipeline(location_input.strip())
st.session_state.pipeline_result = result
st.session_state.chat_history = []
save_session(result, [])   # ← new
```

### Auto-save (chatbot page, after each message)
```python
reply, updated_history = chat(user_input, st.session_state.chat_history)
st.session_state.chat_history = updated_history
save_session(st.session_state.pipeline_result, updated_history)  # ← new
```

### "Load Past Session" expander in sidebar
Added below the "Run Pipeline" section:

```python
with st.expander("📂 Load Past Session"):
    sessions = list_sessions()
    if not sessions:
        st.caption("No saved sessions yet.")
    else:
        options = {s["label"]: s for s in sessions}
        chosen_label = st.selectbox("Select session", list(options.keys()))
        if st.button("Load", use_container_width=True):
            result, history = load_session(options[chosen_label]["path"])
            st.session_state.pipeline_result = result
            st.session_state.chat_history = history
            st.rerun()
```

Loading overwrites the current session state. The existing Map & Scores, Report, and Chatbot pages require no changes — they already read from `st.session_state`.

| File | Change |
|------|--------|

## Out of Scope
- Session deletion UI (files can be removed manually from `sessions/`)
- Session naming / renaming
- Multi-user support
